# Сервер (Supabase): запуск

Нужны: аккаунт Supabase, Supabase CLI, токен бота от @BotFather.

1. Создать проект в Supabase. В **Authentication → Providers → Email** оставить email включённым, «Confirm email» можно выключить (функция сама подтверждает).
2. SQL Editor: выполнить `schema.sql`, затем `seed_regions.sql` (141 код регионов), затем `shop.sql` (магазин: рамки, титулы, эффекты, платный регион; он же закрывает права на служебную функцию `commit_plate_fee`). Затем `cases.sql` (кейсы с машинами, см. раздел ниже; запускать после `schema.sql`, иначе `reset_progress` из schema затрёт версию с машинами). Схема ни разу не запускалась на живой базе: если будут ошибки, пришлите текст.
3. Секреты функций:
   ```
   supabase secrets set BOT_TOKEN=<токен бота> PASSWORD_PEPPER=<длинная случайная строка, например openssl rand -hex 32>
   ```
   `PASSWORD_PEPPER` менять нельзя: от него зависят пароли всех игроков.
4. Деплой: `supabase functions deploy tg-auth`, `supabase functions deploy generate`.
   У `tg-auth` включить «verify JWT = off» (`--no-verify-jwt`): её зовут до входа.
5. В `_shared/cors.ts` заменить `*` на домен Mini App перед выходом в прод.

Логика: клиент шлёт `initData` в `tg-auth`, получает сессию (access/refresh token) и дальше зовёт `generate` и SQL-функции (`supabase.rpc`) с этим JWT. Баланс, цены и редкость считает только сервер.

Тесты `npm test` проверяют, что серверный движок даёт те же результаты, что клиентский, и что проверка подписи Telegram работает.

## Магазин (shop.sql)

- **Платный регион.** Прокрут с выбранным регионом стоит 3000 ₽ + доплата `REGION_FEE_BASE × mult²` (округление до 100). «Все регионы» бесплатно. Доплату считает `generate` (`regionFee` в `_shared/engine.ts`) и списывает атомарно в `commit_plate_fee`. Клиент зеркалит формулу в `config.js` (`regFee`) только для показа цены.
- **Эффекты ника, фоны сцены, витрина.** Слоты `nick`, `bg` надеваются как рамки; `show` (предмет `showcase`) только покупается и открывает до 3 закреплённых номеров в профиле: выбор сохраняет `set_showcase`, чужую витрину отдаёт `get_showcase`. Если `shop.sql` уже запускали, выполните `shop_v2.sql` (безопасно повторять).
- **Косметика.** Каталог в таблице `shop_items` (зеркало: `SHOP` в `js/config.js`, сверяет `tests/shop.test.mjs`). Купленное лежит в `players.owned`, надетое в `players.equip` (`skin`, `title`, `drop`). Титулы и рамки других игроков отдаёт `get_styles(ids)`.
- Цены и множители подбираются константами: `REGION_FEE_BASE` в `_shared/engine.ts` и цены в `shop.sql` + `config.js`.

## Кейсы (cases.sql)

Порядок в SQL Editor: `schema.sql` → `seed_regions.sql` → `shop.sql` (+ `shop_v2.sql`, если нужен) → `cases.sql`. Файл можно запускать повторно; после правки таблиц просто выполните его заново.

- **Машины игрока.** `players.cars text[]`, изначально пусто, машина появляется только из кейса. Клиент не может записать её сам: на `players` нет прав на изменение, машину выдаёт только `open_case`.
- **Таблицы.** `car_classes` (стоимость класса 0..4), `car_defs` (машины и их класс, зеркало `js/data/cars.js`), `case_defs` (цена и веса классов в %, сумма строго 100; зеркало `CASES` в `js/config.js`). Читать можно всем, менять нельзя.
- **`open_case(case_id)`** (только authenticated): в одной транзакции под блокировкой игрока проверяет баланс, списывает цену, выбирает класс по весам (`random()`), затем машину внутри класса. Класс без машин пропускается, его шанс уходит остальным. Новая машина добавляется в `players.cars`; дубликат возвращает `DUP_PCT`% стоимости класса. Ответ: `{car_id, dup, refund, player: {balance, cars}}`. Не хватает денег: ошибка `not enough rub`, клиент превращает её в `{err:1, need}`.
- **`reset_progress`** пересоздана в `cases.sql`: очищает `cars`.
- **Новая машина:** строка в `CARS` (`js/data/cars.js`, картинка в `img/cars/`) и строка `(id, r)` в `car_defs` в `cases.sql`, затем выполнить файл заново. Она сама попадёт во все кейсы, где у её класса `r` вес больше нуля.
- **Новый кейс или правка шансов:** строка в `CASES` (`js/config.js`) и в `case_defs` (+ id в списке в `delete from case_defs` внизу), веса в сумме 100. Тесты проверяют совпадение и то, что кейс нельзя «накрутить» возвратами за дубликаты.

## Рынок игроков (market.sql)

Игроки продают номера друг другу за рубли. **Выполнять последним**: после `schema.sql` → `seed_regions.sql` → `shop.sql` (+ `shop_v2.sql`) → `cases.sql` → `market.sql`. Файл переопределяет `reset_progress` (версия из `cases.sql` плюс очистка рынка), поэтому `cases.sql` после него повторно не запускать. Безопасно повторять.

- **Как устроено.** Выставленный номер уходит из `plates` в `market_listings`: его нельзя продать, обменять или автопродать. При покупке или снятии с рынка он возвращается в `plates` (у номера новый id). Продавец получает цену минус комиссия, комиссия исчезает из игры (слив денег).
- **Правила** (константы в самих функциях, зеркало `MARKET` в `js/config.js`, сверяет `tests/market.test.mjs`): комиссия 5%, цена лота от 1 000 до 100 000 000 000 ₽, не больше 10 лотов на игрока. Чтобы изменить, поправьте и в `market.sql` (`fee_pct`, `min_ask`, `max_ask`, `max_lots`, `check` в таблице), и в `config.js`.
- **Функции** (все `security definer`, права только у `authenticated`): `market_list_plate`, `market_cancel`, `market_buy`, `market_browse` (лента по 30, фильтр по редкости, сортировка), `market_mine` (мои лоты и непрочитанные продажи), `market_ack_sales`. Таблицы `market_listings` и `market_sales` закрыты RLS, напрямую клиент их не читает.
- **Покупка** атомарна: лот и оба игрока блокируются (игроки в порядке id, чтобы встречные сделки не зависали), проверяются деньги и место в коллекции. Купить свой лот, купить уже проданный или снять чужой нельзя.
- **Уведомления.** Клиент раз в 20 секунд спрашивает `market_mine`; о проданном номере показывает плашку и вызывает `market_ack_sales`.
- Схема не запускалась на живой базе: если будут ошибки, пришлите текст.


## Аукцион (auction.sql)

Развитие рынка: продавец задаёт стартовую цену и срок (1, 6, 12 или 24 часа), остальные делают ставки. **Выполнять после** `market.sql` и `bank.sql`, **до** `prestige.sql` (он и `market.sql` вызывают `auction_reset`, если файл запущен). Безопасно повторять. Клиент: `js/views/auction.js`, плитка «Аукцион» в меню.

- **Надёжность.** Ставка замораживается: сумма списывается с баланса сразу, прежнему лидеру она возвращается в той же транзакции. По окончании в одной транзакции под блокировкой лота номер уходит победителю, продавец получает ставку минус комиссия 5% (исчезает из игры). Нет ставок: номер возвращается продавцу. Потерять деньги или номер нельзя, победитель не может потратить замороженное.
- **Расчёт без cron.** Просроченные лоты закрывают `auction_browse`, `auction_mine` и `auction_create`; клиент опрашивает `auction_mine` раз в 20 секунд, а открытый экран сам просит закрыть лот в момент нуля. Если нужно закрывать строго по времени, добавьте pg_cron: `select public.auction_settle_due()` раз в минуту.
- **Защита от накрутки.** Анти-снайпинг: ставка в последние 120 секунд переносит конец на «сейчас + 120 с», суммарный перенос не больше 2 часов (потолок, чтобы торги не шли вечно). Минимальный шаг `max(5%, 100 ₽)`. Продавец не может ставить на свой лот и снимать лот после первой ставки. Лидер не перебивает сам себя. Подставной покупатель продавца только теряет 5% комиссии, денег из воздуха нет. Не больше 5 аукционов на игрока.
- **Константы** живут в функциях (`fee_pct`, `min_ask`, `max_ask`, `max_lots`, `step_pct`, `min_step`, `snipe_s`, `ext_max_s`) и зеркалятся в `AUCTION` (`js/config.js`); совпадение проверяет `tests/auction.test.mjs`.
- **Коллекция.** Ставить можно, только если в коллекции есть место. Номер победителя кладётся в коллекцию при закрытии даже если место успело кончиться (лимит временно превышен: новые номера не выпадут, пока не освободите место).
- **Перерождение** недоступно, пока есть свои аукционы или лидирующая ставка. **Сброс прогресса** снимает свои лоты (ставка лидера возвращается) и обнуляет свои ставки.
- Схема не запускалась на живой базе: если будут ошибки, пришлите текст.


## bank.sql: Банк

Обмен ₽ ↔ $, вклады (1/3/7 дней), буст удачи, слоты рынка, кейсы и эксклюзивные титулы за $.
Порядок запуска в SQL Editor: `schema.sql`, `seed_regions.sql`, `shop.sql`, `cases.sql`, `market.sql`, `bank.sql`. Все файлы идемпотентны (create or replace), `bank.sql` запускать ПОСЛЕДНИМ и `market.sql` тоже запускать заново, если он старый: лимит лотов теперь `10 + extra_lots`, а `reset_progress` вызывает `bank_reset`.
Досрочное закрытие вклада (`bank_deposit_cancel`): в любой момент до конца срока возвращается вложенная сумма без процентов; первые 5 минут штрафа нет (на случай ошибки), потом штраф 10% от вложенного (исчезает из игры). Вклад, срок которого вышел, закрывается обычным «Забрать». Константы `cancel_pct`, `grace_min` зеркалятся в `BANK.cancel` (`js/config.js`), их сверяет `tests/bank.test.mjs`. Если `bank.sql` уже запускали, выполните его заново: безопасно, проданный тираж титулов не сбрасывается.
Титулы банка — ограниченный тираж: `bank_items.supply` (всего) и `bank_items.sold` (куплено); сменить тираж — поправить `update public.bank_items set supply = ...` в `bank.sql` и `max` в `BANK.items`. Повторный запуск файла `sold` не сбрасывает.
Цены, курсы, проценты и лимиты живут только в SQL; зеркало для показа в `js/config.js` (`BANK`), его сверяет `tests/bank.test.mjs`.
Буст удачи читает Edge Function `generate`, её нужно задеплоить заново: `supabase functions deploy generate`.

## leaderboard.sql: Рейтинг

`get_leaderboard(p_kind)`: `'best'` — по самому дорогому выбитому номеру, `'coins'` — по монетам на балансе. Файл запускать заново (старая версия без аргумента удаляется). Клиент: вкладки в `js/views/top.js`.


## types_v2.sql: новые типы номеров

Типы `transit`, `military`, `diplomat`, `retro` (к прежним `civil`, `taxi`, `police`). На живой базе выполните `types_v2.sql` (меняет check по `type` в `plates` и `market_listings`, безопасно повторять) **до** деплоя новой версии `generate`, иначе вставка редкого типа упадёт. Функции (`commit_plate`, `autosell`, `sell_plates`, рынок) типов не перечисляют: «спецномер» для автопродажи это всё, что не `civil`. `prestige.sql` заново запускать не нужно. Деплой: `supabase functions deploy generate`.
В Беларуси выпадают только `civil`, `taxi`, `police`, `transit`; шансы для страны пересчитываются на сумму её типов (поле `c` в `TYPES`). Шансы, множители и форматы живут в `_shared/engine.ts` и зеркалятся в `js/config.js` (сверяет `tests/types.test.mjs`). Баланс: `node --experimental-strip-types --no-warnings tests/balance-sim.mjs` (миллион прокрутов плюс точное ожидание цены).
